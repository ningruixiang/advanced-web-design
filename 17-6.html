async / await 核心代码（和动画一一对应）
下面就是驱动上面动画的真实代码，Promise 工厂 + async 主流程 + Promise.all 并行，没有任何魔法。
// ① 通用：把 setTimeout 包装成 Promise（生产中的标准套路）
function delay(ms, label) {
  return new Promise(resolve => {
    setTimeout(() => resolve(label + " ✔"), ms);
  });
}

// ② 串行步骤：前一个 resolve 才会执行后一个
async function makeDumplings() {
  let start = performance.now();
  const speed = document.getElementById("#yl_speed").value;

  const bought  = await delay(1500 * speed, "买原料");     // 步骤 1
  const got     = await delay(800  * speed, "取原料");      // 步骤 2

  // ③ 并行：和面和馅同时开始，全部完成才往下走
  const [ dough, filling ] = await Promise.all([
    delay(2000 * speed, "和面"),
    delay(1600 * speed, "和馅"),
  ]);

  const wrapped = await delay(1800 * speed, "包饺子");  // 步骤 4
  const eaten   = await delay(1200 * speed, "吃饺子");  // 步骤 5

  const total = performance.now() - start;
  console.log("🥟 完成！总耗时:", total.toFixed(0) + "ms");
}

makeDumplings();
Promise 速查表
6 种组合 / 静态方法 / 状态切换，一句话记住。
API作用何时 resolve / reject
new Promise(fn)创建异步对象，fn 同步执行resolve(val) / reject(err)
.then(onFulfilled, onRejected)接结果 / 接错误前一个 Promise 结束后触发
.catch(onRejected)接错误的语法糖等价于 .then(null, fn)
.finally(fn)无论成败都执行不改变 Promise 状态，常用于清理 loading
Promise.all([p1, p2])并行，等全部成功才 resolve一个失败立刻 reject（快速失败）
Promise.allSettled([...])并行，不管成败都走完返回 [{status, value/reason}, ...]
Promise.race([...])并行，谁先结束就跟随谁首个 settle 的 Promise 决定状态
Promise.any([...])并行，首个成功就 resolve全部失败才 reject（AggregateError）
async function fn()async 声明，函数自动返回 Promise函数体 throw → reject；return → resolve
await expr把 Promise 拆成同步代码只在 async 函数内可用
