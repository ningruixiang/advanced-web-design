② 数据模型 ER 图

erDiagram 11 个实体

覆盖"用户—会话—消息—知识"主线，以及转人工后产生的工单链路与满意度的弱实体（会话到评价、会话到工单均为可空的一对一）。

erDiagram USER ||--o{ SESSION : "发起" USER ||--o{ ORDER : "拥有" SESSION ||--o{ MESSAGE : "包含" SESSION ||--o| SURVEY : "产生" SESSION ||--o| TICKET : "转人工" AGENT ||--o{ TICKET : "受理" TICKET ||--o{ TICKET_LOG : "记录" KNOW_CATEGORY ||--o{ KNOWLEDGE : "归类" KNOWLEDGE ||--o{ KNOW_CHUNK : "切分" MESSAGE }o--o{ KNOWLEDGE : "引用" USER { bigint user_id PK "用户主键" varchar nickname "昵称" varchar phone "手机号" varchar member_level "会员等级" datetime created_at "注册时间" } ORDER { bigint order_id PK "订单号" bigint user_id FK "所属用户" decimal amount "订单金额" varchar status "订单状态" datetime created_at "下单时间" } SESSION { bigint session_id PK "会话主键" bigint user_id FK "所属用户" varchar channel "接入渠道" varchar state "会话状态" datetime started_at "开始时间" datetime ended_at "结束时间" } MESSAGE { bigint message_id PK "消息主键" bigint session_id FK "所属会话" varchar role "user / assistant / agent" text content "消息内容" float confidence "意图置信度" datetime created_at "发送时间" } SURVEY { bigint survey_id PK "评价主键" bigint session_id FK "关联会话" tinyint score "1-5 分" varchar comment "用户留言" datetime created_at "提交时间" } TICKET { bigint ticket_id PK "工单号" bigint session_id FK "来源会话" bigint agent_id FK "受理坐席" varchar priority "优先级" varchar status "工单状态" datetime created_at "创建时间" } TICKET_LOG { bigint log_id PK "日志主键" bigint ticket_id FK "所属工单" bigint agent_id FK "操作人" varchar action "处理动作" text remark "处理备注" datetime created_at "操作时间" } AGENT { bigint agent_id PK "坐席主键" varchar name "坐席姓名" varchar skill_group "技能组" varchar work_state "在线状态" } KNOW_CATEGORY { bigint category_id PK "分类主键" varchar name "分类名称" bigint parent_id FK "父分类" int sort "排序" } KNOWLEDGE { bigint knowledge_id PK "知识主键" bigint category_id FK "所属分类" varchar title "问题标题" text answer "标准答案" varchar source "来源文档" varchar status "发布状态" datetime updated_at "更新时间" } KNOW_CHUNK { bigint chunk_id PK "片段主键" bigint knowledge_id FK "所属知识" text chunk_text "片段文本" varchar embedding_model "向量模型" int token_count "令牌数" }
实体含义关键字段
USER / ORDER用户与订单，为客服提供身份与业务上下文user_id、member_level、amount、status
SESSION / MESSAGE会话与消息，记录多轮对话及每轮的意图置信度channel、state、role、content、confidence
TICKET / TICKET_LOG / AGENT转人工后的工单、处理日志与坐席信息priority、status、action、skill_group
KNOW_CATEGORY / KNOWLEDGE / KNOW_CHUNK知识库三层结构：分类 → 知识条目 → 检索片段parent_id、title、answer、chunk_text、embedding_model
SURVEY会话满意度评价，用于回流评测与模型迭代score、comment

本例要点

  • Mermaid 离线引入：<script src="cdn/mermaid.min.js">，文件从 CDN 下载后放于 cdn/ 目录。
  • 页面中图表源码直接写在 <div class="yl_mermaid"> 里，脚本调用 mermaid.run({ nodes: ... }) 批量渲染，不对源码做转义。
  • 统一主题：mermaid.initialize({ theme: 'base', themeVariables: {...} })，流程图用 classDef 按节点性质着色，ER 图用关系基数表达"一对多 / 可空一对一"。
